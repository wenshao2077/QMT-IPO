# 东方与东北双账户打新

## 实现范围

从东北已部署提交 `d1f4d09b246e71fe9d9bcf874138628341f358bb` 派生。共用日历、发行元数据、沪深额度、数量和时段、防重复、每日核对、通知和备份引擎。每个账户独立安装、配置、SQLite账本、原生claim、任务命名空间和桌面入口；不复制账户持仓、策略或历史账本。

`transport=xtquant` 使用显式 `userdata_mini` 或 `userdata`。`transport=native` 使用独立大QMT内置模型与固定本机文件目录。界面为大QMT不能证明SDK可用，目录中有IPC文件也不能证明可连接；禁止运行中自动回退或同时启用两种传输。

2026-10-26 本机东方两处SDK路径只读连接均返回-1。原生路线是东方当前适配对象；东北既有部署继续使用其独立SDK配置，本分支不会自动升级东北。

## 原生接口与共存

原生桥完全新建，不导入QuantClass/Rocket或变更16666/16667。QMT Python 3.6模型通过1秒独立timer处理最多一条本地请求，每轮让出20ms。3.11外部引擎保持原环境，模型自身只用标准库。请求与响应绑定协议、账户摘要、任务前缀、代码SHA、原生会话、PID和有效期；不开放网络端口。

- 查询：`get_ipo_data()`、`get_new_purchase_limit(account)`、`get_trade_detail_data(account,'STOCK','ACCOUNT'/'ORDER')`。
- 账户：恰好一个账户、明确正常状态、券商业务日为当天。
- 委托：全表核对账户、证券、状态、日期和时间。备注无法解码保留行，不用当前时间填补坏日期。
- 申购：固定`passorder(23,1101,account,code,11,price,quantity,'AutoIPOv2',2,remark,ContextInfo)`，没有签名回退、撤单、卖出或普通股票交易动作。
- `passorder`没有返回值；进入待核对后只按实际委托唯一匹配确认。调用异常、超时或崩溃都不重发。
- 原生调用前复验当日发行信息、额度、整手、价格、已有委托、日历、业务日、窗口、执行开关与授权回执。在账户×日期×申购代码的独占claim落盘后只调用一次。claim永不自动删除，切换路径继续使用同一账户原账本。

官方依据：[交易接口](https://knowledge.thinktrader.net/docs/python/trading_function.html)、[新股申购示例](https://dict.thinktrader.net/innerApi/code_examples.html)、[数据结构](https://knowledge.thinktrader.net/docs/python/data_structure.html)、[XtQuant新股和新债单位](https://knowledge.thinktrader.net/docs/cloud/xtquant_xttrader.html)。本机东方安装内官方Python API PDF第108页亦确认发行和额度接口。申购不套普通股票全额现金预占；中签缴款、卖出不属于本工具。

## 安装、验收和切换

先`setup.ps1 -Operation VerifyPackage`与`Plan`。东方新实例使用`New -Root <独立目录> -TaskPrefix QmtIPO-Oriental -InstallDependencies`，默认四任务及执行均关闭。首次配置完成后`setup.ps1 -Operation PrepareNative -Root <目录> -ConfirmPrepare`生成绑定该目录的`native_loader.py`，保留关闭状态。在QMT中新建独立实盘模型加载该loader；init/handlebar不会申购，只有明确启用且收到有效申购请求才有提交路径。

`probe_readonly.py --config <实例/config.json>`验账户、全部委托、发行和额度；`instance_monitor.py --root <目录>`同时核验账本与连接，不发送通知、不重启、不下单。多机外部监测使用私有manifest，`monitor_brokers.py --manifest <私有JSON>`对每家分别留证；源码没有账户/密钥/主机私有配置。原生模型未装载、账户字段未知或SHA不匹配均报错，不冒充正常。

切换先暂停该实例，关闭其全部四任务并等待worker自然退出，再通过`setup.ps1 -Operation RebindClient -QmtUserdata <显式目录> -Transport xtquant|native -ConfirmRebind`改路径/传输；不改账户、state_dir或历史意图。再次只读验收后才恢复每日执行。原生目录保持该实例固定位置；不要新建账本绕过旧意图。

启用每日真实申购需要Owner对具体实例作最终确认。代码、离线测试、安装、原生模型连接、自然调度、券商受理分别验收；没有实际发行项目时不能宣称新股/新债实单验收通过。

## 批准明日起生效与推送地址待提供

Owner可明确设置`execution_start_date=YYYY-MM-DD`，四任务各自的日触发器及Cycle登录触发器也绑定该日。Launcher、Coordinator和原生调用末端分别拒绝生效日前的真实提交；只读探针仍可核验当日接口。生效日前的健康检查显示`waiting_activation`，不把今天未运行误报漏单。旧实例省略该字段时保留原行为。

当Owner明确允许先运行、稍后提供推送地址时，使用`notification_mode=pending_address`并清空该实例活动Webhook文件，原地址仅留受保护备份。业务结果及监控事件继续持久化，所有发送入口与测试发送均阻断，不读取旧地址，不增加投递尝试，也不把有意延后推送记为任务失败。省略该字段仍默认`enabled`，不会影响东北既有实例。

收到Owner新地址后，将地址写入该实例独立私有文件并切回`enabled`，后续Notify/Monitor任务消费各自原队列；不删消息、不伪造送达、不重跑申购。地址不得进入源码、任务参数或日志。启用日、任务及通知模式以各实例私有激活回执为准。
