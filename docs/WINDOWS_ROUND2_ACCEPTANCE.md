# 第二阶段 Windows 增量验收

基线alpha1：用户已确认验收；不重复声称该用户没有验收。本清单只针对alpha2新增或改变的部分。网页开发未执行Windows实机、真实账户或生产部署。

先记录待验收ZIP SHA-256、Windows版本、Python完整版本/位数、SQLite实际版本、SDK/客户端版本与桌面缩放。隔离假账号目录，不与生产固定任务名冲突；禁止在生产注入故障。

| 项目 | 通过标准 |
|---|---|
| 全部Python测试 | 原165项加本轮新增测试；如有失败/跳过逐项保留，不改成通过 |
| PS5.1和PS7 | test_tasks.ps1解析所有脚本；新五个非交易入口输出有效JSON与准确退出码 |
| 日历维护页 | 2026-12-26显示2027-01-01缺口；2027-01-02仍显示下一周一未知；不连接账户 |
| 通知损坏 | 隔离监控SQLite损坏时总数为未知而非零；暂停时仍显示通知失败 |
| 送达时间 | 使用本地fake sender测试：失败不记成功时间，成功后有时间；旧delivered和抑制消息不补造 |
| UI | 100%/125%/150%缩放下“维护与诊断”可读；取消导出和取消选路径不产出文件 |
| 本地导出 | 只生成明确选择的新ZIP；中文/空格路径有效；拒绝覆盖、安装/状态/QMT目录内输出 |
| 脱敏 | 使用假账号和标记密钥；ZIP、stdout、出错结果均不包含它们；没有原始日志/数据库 |
| 恢复建议 | 有configuration-pending/maintenance标记时只输出建议，文件保持，任务不变 |
| ZIP验证 | 原包通过；篡改单文件、重复成员、未知文件、大小写碰撞、错误外部SHA均失败 |
| 升级与回滚 | 受控包装器：原配置与账本历史保持，旧送达数据不变；回滚后新增通知旁路表不删 |
| 运行时风险 | 核对SQLite实际版本及供应商修复，关联SDK兼容记录，不自动替换DLL |

真实通知、账户读取和自然申购回报仍属于单独获准的验收操作；本清单中的假发送器成功不代表企业微信实际送达。结果应逐项记录已测/失败/未测，附日志并绑定当前包指纹。没有证据的券商组合不填入兼容矩阵。
