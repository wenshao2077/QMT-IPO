# 项目结果图片通知

2026-10-27，Owner要求东方证券打新通知在展示层对齐东北证券的图片播报。既有图片只接收全部正常的结果，因此“千红发债｜废单待核对”此前进入文字通道。

## 展示与兼容

继续使用原图片版式、日期、券商标题、名称与新股/可转债类型。正常受理状态保持原“申购成功”展示及卡片序列化身份；已报转已确认不重复排队。待确认、意图已登记、结果不确定、部分成交、等待申报、额度不足与窗口结束各有明确文字；废单、撤单及异常委托使用红色状态，其他待处理使用橙色。券商错误回报显示在卡片说明行，沿用配置脱敏。

每页最多六项，未启用市场仍隐藏；数量、订单号和事件编号不加入卡片。底部保留“申购结果 · 非中签结果”。不把待核对或废单显示为成功。

连接/查询错误、日历问题、未知项目状态及无法识别的品种保留文字告警。预览运行保留原文字；尚未完成且没有可展示项目时不生成“今日未申购”。混合结果逐项保留真实状态。

## 通知与执行边界

继续使用原outbox、PNG/base64/MD5与成功回执，图片渲染/发送失败保持重试。兼容既有V1成功卡片；不改写已排队或已送达的历史文字，不补造送达时间，不主动补发今日结果。重复的同一可见结果只排队一次，实际状态变化可以生成更新卡片。

本轮仅改变结果展示与分流，不改变申购、数量、时段、防重、账户、账本、原生桥、任务定义或开关。东方实例受控升级；东北当前安装保持，不能由共享源码更新推断其已部署。

## 验证入口

`test_notification_card`覆盖各类已知业务状态、混合结果、券商错误、未知/系统错误回退、旧成功卡片兼容、分页、真实Windows中文PNG、HTTP图片请求体与重试。合成业务验证废单重复核对只生成一次变更通知且不重复申购。全套测试、成品包及部署回执各自绑定实际结果，不能把图片生成当作消息送达。
