# 2026-10-26 连接、委托解析与监控兼容修复

## 故障与修复范围

现场同一套 xtquant 250807.1.2 对旧 `userdata_mini` 返回连接失败，对实际 `userdata` 连接、订阅和账户查询成功。界面是否为大 QMT、是否为受邀券商与实际 IPC 路径分别核对；程序显式绑定配置目录，不自动扫描、回退或切换账户。

51 条原生委托中有 16 条 `order_remark` 属性读取抛出 UnicodeDecodeError，旧代码因此中断整表核对。新代码保留所有委托行，将备注标记为 `decode_failed`，不把它伪装成正常空字符串。账户、时间、证券、委托号或状态等核心字段读取失败仍阻断整轮。零委托号原有兼容和负号拒绝规则保留；提交返回值仍要求正整数。

已登记且有可靠委托号的意图继续按号核对；缺号且同证券存在不可读备注时不认领、不重发。既有 INTENT、UNCERTAIN 等账本状态不变；旧成功记录本轮无法唯一核实时，界面为 UNCERTAIN，不能沿用旧成功冒充本轮核对。先核对、持久化意图、最多首次提交、15:05 仅核对等规则保持。

连接、订阅、账户就绪与委托查询分别诊断。运行详情显示脱敏返回码、字段和解析数量。监控对“连接未完成，尚未查询到项目”单列原因，不再提示为已经发现待申购项目。

## 验收与迁移入口

只读候选验收使用：

```powershell
python -B probe_readonly.py --config <原实例配置> --qmt-userdata <已核实的实际接口目录>
pwsh -NoProfile -File probe_qmt_trade.ps1 -InstallRoot <原实例根> -QmtUserdata <已核实的实际接口目录>
```

路径覆盖只保存在该只读进程内；不运行 cycle、不读写申购意图或通知队列，不发送消息。交易通道探针直接检查 SDK 连接、订阅和账户状态，不以 miniquote 缺席或旧日志缺失判定新客户端断线；探针子进程限时 20 秒，只清理自身子进程。

生产迁移必须先 VerifyPackage、Plan 并完成测试。使用原控制入口暂停并确认四任务禁用、无在途 worker，才允许：

```powershell
pwsh -File setup.ps1 -Operation RebindClient -Root <原实例根> -QmtUserdata <实际接口目录> -ConfirmRebind
```

RebindClient 只修改 `qmt_userdata`，先保留私有配置原字节备份，保留原账户、账本路径、市场与关闭状态；不启动任务、不连接账户、不启用交易。未完成安装、维护中、缺失/损坏账本、任务未禁用或配置并发变化均拒绝。代码升级仍使用原 Upgrade 流程，不能逐文件覆盖生产目录。

外部 QuantPush 适配由 `prepare_monitor_adapter.py` 输出到新的独立目录：

```powershell
python -B prepare_monitor_adapter.py --monitor-root <原监控目录> --ipo-root <正式打新实例> --output <新暂存目录>
```

它只暂存脚本和原/新哈希回执：旧探针转接到新 SDK 只读探针，watch_live 以交易接口检查代替 mini-only 进程门禁，保留 Rocket、Fuel、账户心跳、数据端口和通知策略；存在盘前监控时同步修正其恢复文案，不安装、不运行、不发送。安装前须核对原哈希，不能把暂存当部署完成。

本轮先完成隔离测试与目标机只读候选验收，不自动切换生产配置或运行当日申购循环，避免恢复连接后追补。Guardian 的 WinError 740 启动权限属于另一条重启执行链，本补丁不改其启动权限或重启策略。
